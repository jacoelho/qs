# Primary-source architecture comparison

Sources inspected on 2026-10-29. Go repository links are pinned to the commits
already selected for the project review. jOOQ links below reference its live
`main` branch or current 3.21 documentation; no commit pin is claimed.

| Source | Observed design | Application to qs |
| --- | --- | --- |
| [jOOQ SelectSelectStep](https://github.com/jOOQ/jOOQ/blob/main/jOOQ/src/main/java/org/jooq/SelectSelectStep.java#L85-L122) | Select accepts both Java varargs and collections. Its own documentation discourages storing step interfaces in client code, citing mutable implementations, composition difficulties, readability and binary compatibility. | Keep concrete Go roles at meaningful grammar transitions. Build reusable components independently; do not reproduce a large Java step-interface hierarchy. Go variadics already accept expanded slices. |
| [jOOQ dynamic SQL](https://www.jooq.org/doc/latest/manual/sql-building/dynamic-sql/) | Expressions, collections and predicates can be built outside the fluent chain and reused. | Make dynamic collection boundaries ordinary calls. Reusable expression collections are valuable independently of query builders. |
| [jOOQ noCondition](https://www.jooq.org/doc/latest/manual/sql-building/dynamic-sql/no-condition/) | The sentinel omits conditions and empty clauses; in column-producing contexts it leads to a NULL projection. Model API behavior is undefined. | Do not borrow context-dependent omission through zero expressions. Conditional slice assembly keeps absence explicit and preserves invalid-zero checks. This is a design inference, not a claim that jOOQ is incorrect. |
| [jOOQ generated tables](https://www.jooq.org/doc/latest/manual/code-generation/codegen-object-types/codegen-tables/) | Generated tables expose typed fields and return the same generated table type when aliased. | Schema generation can improve typo/type correctness, but is a separate schema/toolchain commitment. Relation-taking projection factories solve current alias reuse without it. |
| [jOOQ bind values](https://www.jooq.org/doc/latest/manual/sql-building/bind-values/) | SQL and values remain separate for binding; the library does not internally cache prepared statements. | Preserve qs placeholders plus argument slices. Query rendering measurements do not imply database execution improvements. |
| [Squirrel column methods](https://github.com/Masterminds/squirrel/blob/1ded5784535dcffa4e175d4efbd1ca2706927758/select.go#L257-L278) | Variadic column input; expression columns accept separately bound arguments. | Confirms familiar Go slice-expansion calling style; qs can keep its narrower expression roles. |
| [goqu Select](https://github.com/doug-martin/goqu/blob/21b6e6d1cb1befe839044764d8ad6b1c6f0b5ef4/select_dataset.go#L201-L241) | Select copies a dataset with new clauses; an empty list resets the projection to its default. | Copying and empty-list semantics are separate choices. Explicit empty write targets in qs must stay invalid rather than silently choose a default. |
| [Bob query mods and generation](https://github.com/stephenafamo/bob/blob/02f57ef504662b042a5dc182d39a3ce349043ce2/README.md#L54-L83) | Query construction uses modifiers; schema-generated modifiers add type information. | Modifier composition is an alternative to fluent stages, but does not itself prove grammar or schema correctness. Its extra abstraction needs a caller benefit beyond accepting slices. |
| [sqlc](https://github.com/sqlc-dev/sqlc/blob/3ad8b20fb02b5bea81591b673da0758b8685d951/README.md#L6-L10) | SQL source is compiled into typed calling interfaces. | A strong separate architecture for known query shapes. It changes qs's dynamic-query purpose rather than resolving a collection boundary. |
| [Jet generation](https://github.com/go-jet/jet/blob/d18395ad6a34916c28748f8105e05ce826a852e7/README.md#L101-L124) | Generates SQL-builder and model types from a database schema. | Like jOOQ, generated fields merit a separate schema-aware layer, with generation and freshness obligations. |
| [Bun SelectQuery columns](https://github.com/uptrace/bun/blob/3c2bd0543e9390225f73bba4004d789d10c25f31/query_select.go#L134-L146) | Variadic columns mutate and return the receiver; expressions carry query arguments separately. | Familiar fluent syntax does not establish immutability. Document qs's captured slice positions and live nested query references explicitly. |

The application column contains local design conclusions. These sources were not
benchmarked against qs, and no comparative performance ranking is inferred.
